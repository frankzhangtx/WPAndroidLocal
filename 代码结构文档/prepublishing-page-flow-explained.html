Feature Analysis

WordPress Android 易发布页面流程分析

这份文档沿着真实源码串起“从编辑器打开易发布页面 -> 底部页导航到子页 -> 返回首页 -> 交给宿主 Activity 提交”的主链路。 代码上它不是一个单文件逻辑，而是由 EditPostActivity、GutenbergKitActivity、 PostsListActivity、PrepublishingBottomSheetFragment、 PrepublishingViewModel 和 PrepublishingHomeViewModel 协同完成。

主入口：WordPress/src/main/java/org/wordpress/android/ui/posts/EditPostActivity.kt
块编辑器入口：WordPress/src/main/java/org/wordpress/android/ui/posts/GutenbergKitActivity.kt
列表页入口：WordPress/src/main/java/org/wordpress/android/ui/posts/PostsListActivity.kt
核心状态机：WordPress/src/main/java/org/wordpress/android/ui/posts/prepublishing/PrepublishingViewModel.kt
我的结论

易发布页面本质上是一个“预提交状态机”。用户在这里看到的是发布日期、标签、分类和社交联动， 但真正的发帖动作并不在底部页内完成，而是通过 onSubmitButtonClicked() 把结果回传给宿主 Activity， 再由宿主统一执行 uploadPost()。

页面负责组织状态，不负责真正上传 首页按钮文案由 Post 状态决定 返回逻辑先回首页，再允许关闭底部页
阅读顺序

先看入口为什么会打开底部页，再看 ViewModel 如何控制页面切换，最后看首页如何拼装内容并触发提交。

入口层

performPrimaryAction() 在编辑器里决定是否打开易发布页；PostsListActivity 也能直接从列表页拉起它。

状态层

PrepublishingViewModel 维护当前屏幕：HOME、PUBLISH、TAGS、CATEGORIES、ADD_CATEGORY、SOCIAL。

渲染层

PrepublishingHomeViewModel 拼装首页列表，PrepublishingHomeAdapter 只渲染可见项。

边界层

真正的提交动作回到宿主 Activity；当前文档只解释“查看易发布页面”这条 UI 流程，不展开上传实现。

流程总览

易发布页面在代码里的真实职责

这条链路的关键不是“点按钮就发帖”，而是先把编辑器中的内容、站点能力和用户意图收口到同一个底部页状态机里。

你可以把它理解成三层：入口层决定是否打开底部页，状态层决定当前页显示什么， 提交层把最终动作回传给宿主 Activity。页面切换全部发生在 PrepublishingBottomSheetFragment 的子 Fragment 容器里，而不是跳到新的 Activity。

入口不止一个

编辑器主按钮、列表页快捷入口都能打开它，但最终都会落到同一个 PrepublishingBottomSheetFragment。

首页不是静态页面

首页内容由 PrepublishingHomeViewModel 动态组装，按钮文案取决于帖子状态与当前用户是否有发布权限。

子页只是“局部编辑”

Publish、Tags、Categories、AddCategory、Social 都只在底部页内切换。

返回语义很重要

返回键先回到首页，再允许关闭底部页；这样不会在编辑半途中误关页面。

2. 入口与触发条件

编辑器宿主里的主按钮不是直接保存就是打开易发布页。对 PUBLISH_NOW、 UPDATE、CONTINUE、SCHEDULE、SUBMIT_FOR_REVIEW， 代码都会先跳到预发布底部页；只有 SAVE 会直接进入本地/在线保存。 

// EditPostActivity / GutenbergKitActivity 的分流逻辑完全同构：
// 绝大多数主按钮都会先打开易发布页面，而不是直接执行上传。
private fun performPrimaryAction() {
    when (primaryAction) {
        PrimaryEditorAction.PUBLISH_NOW -> {
            analyticsTrackerWrapper.track(Stat.EDITOR_POST_PUBLISH_TAPPED)
            showPrepublishingNudgeBottomSheet()
            return
        }

        PrimaryEditorAction.UPDATE,
        PrimaryEditorAction.CONTINUE,
        PrimaryEditorAction.SCHEDULE,
        PrimaryEditorAction.SUBMIT_FOR_REVIEW -> {
            showPrepublishingNudgeBottomSheet()
            return
        }

        PrimaryEditorAction.SAVE -> uploadPost(false)
    }
}

private fun showPrepublishingNudgeBottomSheet() {
    editPostNavigationViewModel.navigateTo(EditPostDestination.Editor)
    ActivityUtils.hideKeyboard(this)
    // 延迟弹出，避免和编辑器切换/键盘收起动画打架。
    showPrepublishingBottomSheetRunnable?.let {
        showPrepublishingBottomSheetHandler?.postDelayed(it, delayMs)
    }
}
补充说明： PostsListActivity 也可以直接调用 PrepublishingBottomSheetFragment.newInstance(site, isPage) 打开同一个底部页。 这意味着“查看易发布页面”既可能从编辑器内部发生，也可能从帖子列表页发生，但落到的 UI 结构是相同的。

3. 底部页状态机

PrepublishingBottomSheetFragment 是容器，真正的页面切换由 PrepublishingViewModel 驱动。 它持有 currentScreen，并通过事件流控制子 Fragment 的切换、关闭和键盘收起。 

// ViewModel 负责“当前在哪一页”以及“下一步要跳去哪一页”。
fun start(site: SiteModel, currentScreenFromSavedState: PrepublishingScreen?) {
    this.site = site

    // 有配置变更就恢复保存的页；否则每次重新打开都从 HOME 开始。
    val targetScreen = currentScreenFromSavedState ?: HOME
    this.currentScreen = targetScreen

    navigateToScreen(targetScreen)

    // 标签只拉一次，避免重复请求。
    if (!tagsFetched) {
        tagsFetched = true
        fetchTags()
    }
}

fun onActionClicked(actionType: ActionType, bundle: Bundle? = null) {
    when (actionType) {
        is ActionType.PrepublishingScreenNavigation -> {
            currentScreen = actionType.prepublishingScreen
            navigateToScreen(actionType.prepublishingScreen, bundle)
        }
        is ActionType.Action -> handleAction(actionType)
    }
}

fun onBackClicked(bundle: Bundle? = null) {
    when {
        currentScreen == ADD_CATEGORY -> {
            currentScreen = CATEGORIES
            navigateToScreen(currentScreen as PrepublishingScreen, bundle)
        }

        currentScreen != HOME -> {
            currentScreen = HOME
            navigateToScreen(currentScreen as PrepublishingScreen)
        }

        else -> {
            _dismissBottomSheet.postValue(Event(Unit))
        }
    }
}

底层容器做的事

PrepublishingBottomSheetFragment 只负责把 navigationTarget 转成子 Fragment，并在 back 键时把控制权交还给 ViewModel。

键盘策略很细

切到 PUBLISH 或 CATEGORIES 时会发出 dismissKeyboard，而切到 HOME、TAGS、ADD_CATEGORY 则尽量保留输入法。

4. 首页如何组装

首页的列表不是写死的。PrepublishingHomeViewModel 会根据帖子状态、是否是页面、站点权限和 Jetpack Social 状态， 动态拼出“站点头部 + 发布日期 + 标签 + 分类 + Social + 主按钮”这些条目。 

// 首页条目由 ViewModel 拼装，Adapter 只负责渲染可见项。
private fun setupHomeUiState(editPostRepository: EditPostRepository, site: SiteModel) {
    val prepublishingHomeUiStateList = mutableListOf<PrepublishingHomeItemUiState>().apply {
        add(HeaderUiState(UiStringText(site.name), StringUtils.notNullStr(site.iconUrl)))

        if (editPostRepository.status != PostStatus.PRIVATE) {
            showPublicPost(editPostRepository)
        } else {
            showPrivatePost(editPostRepository)
        }

        // 页面类型不展示分类条目，文章则会展示分类。
        if (!editPostRepository.isPage) {
            showNotSetPost(editPostRepository, site)
            add(HomeUiState(
                navigationAction = PrepublishingScreenNavigation.Categories,
                actionResult = if (categoriesString.isNotEmpty()) {
                    UiStringText(categoriesString)
                } else {
                    UiStringRes(R.string.prepublishing_nudges_home_categories_not_set)
                },
                actionClickable = true,
                onNavigationActionClicked = ::onActionClicked
            ))
        }

        add(SocialUiState.Hidden)

        // 主按钮文案由 EditorActionsProvider + userCanPublish(site) 决定。
        add(getButtonUiStateUseCase.getUiState(editPostRepository, site) { publishPost ->
            launch(bgDispatcher) {
                waitForStoryTitleJobAndSubmit(publishPost)
            }
        })
    }.toList()

    _uiState.postValue(prepublishingHomeUiStateList)
}

按钮文案来源

GetButtonUiStateUseCase 先通过 EditorActionsProvider.getPrimaryAction() 算出主动作，再映射成按钮 UI 状态。

社交模块是可见性驱动的

SocialUiState.Hidden 是默认值；只有 updateJetpackSocialState() 认为应该展示时，它才会切成可见状态。

关键细节： PrepublishingHomeAdapter.update() 会过滤掉所有 isVisible == false 的项，所以首页结构实际上是“先在 ViewModel 里拼装，再按可见性裁剪”。

5. 子页如何返回

子页不是平行页面，而是底部页内部的“二级视图”。每个页面的返回逻辑都会回到 PrepublishingViewModel 或者回到宿主 Fragment 通过 onBackClicked() / onActionClicked() 再次切换。

Publish Settings

PrepublishingPublishSettingsFragment 只负责日期等发布设置，并通过 navigateToHomeScreen 回到首页。

Tags

PrepublishingTagsFragment 复用标签输入逻辑，保存后回到首页；返回键还会先上报标签变更埋点。

Categories / AddCategory

Categories 负责选分类，AddCategory 负责新增分类；两者通过 bundle 在底部页内部往返。

Social

PrepublishingSocialFragment 直接读取父容器里的 EditorJetpackSocialViewModel，展示社交分享配置。

返回链路的设计重点： ADD_CATEGORY 返回时先回 CATEGORIES，只有回到 HOME 后再次按返回才会关闭底部页。 这能避免用户在编辑分类时一不小心把整个易发布页面关掉。

6. 关键代码片段

下面三段代码分别对应入口分流、底部页状态机、首页组装。它们合在一起就是这条流程的骨架。

6.1 入口分流

编辑器宿主的主按钮会先判断是否进入预发布页；这是“查看易发布页面”的第一道门。

// 这个分支决定用户是否先看到易发布页面。
when (primaryAction) {
    PrimaryEditorAction.PUBLISH_NOW,
    PrimaryEditorAction.UPDATE,
    PrimaryEditorAction.CONTINUE,
    PrimaryEditorAction.SCHEDULE,
    PrimaryEditorAction.SUBMIT_FOR_REVIEW -> showPrepublishingNudgeBottomSheet()
    PrimaryEditorAction.SAVE -> uploadPost(false)
}

6.2 页面路由

容器 Fragment 把 ViewModel 的导航目标换成具体子页，底部页内部完全靠这个路由表运行。

// navigationTarget 决定往底部页容器里塞哪个子 Fragment。
viewModel.navigationTarget.observeEvent(this) { navigationState ->
    navigateToScreen(navigationState)
}

private fun navigateToScreen(navigationTarget: PrepublishingNavigationTarget) {
    when (navigationTarget.targetScreen) {
        HOME -> PrepublishingHomeFragment.newInstance()
        PUBLISH -> PrepublishingPublishSettingsFragment.newInstance()
        TAGS -> PrepublishingTagsFragment.newInstance(navigationTarget.site)
        CATEGORIES -> PrepublishingCategoriesFragment.newInstance(navigationTarget.site, navigationTarget.bundle)
        ADD_CATEGORY -> PrepublishingAddCategoryFragment.newInstance(navigationTarget.site, navigationTarget.bundle)
        SOCIAL -> PrepublishingSocialFragment.newInstance()
    }
}

6.3 首页条目与提交回传

首页按钮点击后不会直接上传，而是把布尔型 publishPost 回传给宿主 Activity。

// 主按钮的点击回调只做两件事：关页和发事件。
fun onSubmitButtonClicked(publishPost: PublishPost) {
    onCloseClicked()
    _triggerOnSubmitButtonClickedListener.postValue(Event(publishPost))
}

// Home 页面会被 Adapter 过滤掉所有不可见条目。
val visibleNewItems = newItems.filter { it.isVisible }
阅读指南

你在源码里应该盯住哪些点

下面这些点能帮助你快速判断一个改动会不会破坏易发布页面的行为。

1. 入口是否一致

编辑器宿主和列表页都能打开底部页，但最终都走同一个容器与同一个 ViewModel。

2. 当前页是否可恢复

KEY_SCREEN_STATE 让配置变更后还能回到上次所在的子页，而不是每次都回到首页。

3. 首页条目是否可见

PrepublishingHomeAdapter 直接过滤掉不可见项，所以 ViewModel 的可见性状态很关键。

4. 主按钮文本是否正确

EditorActionsProvider 决定 Publish / Update / Schedule / Submit for Review / Save 的实际展示。

5. 返回键是不是在走状态机

返回键不是简单 dismiss，而是先回首页，再允许关闭底部页。

6. 社交模块是不是被误展示

只有 EditorJetpackSocialViewModel 判定可显示时，Social 条目才会从隐藏状态变成可见。

范围边界： 这份文档只解释“查看易发布页面”的 UI 流程。如果你要继续追“点了提交以后怎么上传、怎么更新 post 状态、怎么收尾 snackbar”，那已经是另一条更长的发帖链路了。
