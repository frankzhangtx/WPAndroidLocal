LoginSiteApplicationPasswordViewModelTest 中 runApiDiscovery 用例梳理

这份文档只解释一个很窄但很关键的点：在测试 Given ViewModel, when calling runApiDiscovery, then 里， applicationPasswordLoginHelper.getAuthorizationUrlComplete(siteUrl) 的值并不是运行时现算，而是被 Mockito 预先固定成一个字符串，然后被 ViewModel 原样透传到 discoveryURL。

测试文件：WordPress/src/test/java/org/wordpress/android/ui/accounts/login/applicationpassword/LoginSiteApplicationPasswordViewModelTest.kt
实现文件：WordPress/src/main/java/org/wordpress/android/ui/accounts/login/applicationpassword/LoginSiteApplicationPasswordViewModel.kt
辅助类：WordPress/src/main/java/org/wordpress/android/ui/accounts/login/ApplicationPasswordLoginHelper.kt
直接答案 在这个测试里，applicationPasswordLoginHelper.getAuthorizationUrlComplete(siteUrl) 的返回值是 "https://example.com/wp-json/wp/v2/application-passwords/authorization"。 原因是测试在调用前已经用 thenReturn(expectedDiscoveryUrl) 把它 mock 死了。

带中文注释的关键代码

只截取回答这个问题必须看的那几段：测试 stub、ViewModel 透传、真实 helper 的实现入口。

// LoginSiteApplicationPasswordViewModelTest.kt:38-43
fun `Given ViewModel, when calling runApiDiscovery, then `() = test {
    val siteUrl = "https.example.com"
    val expectedDiscoveryUrl =
        "https://example.com/wp-json/wp/v2/application-passwords/authorization"

    // 关键：这里直接规定 mock 返回 expectedDiscoveryUrl
    whenever(applicationPasswordLoginHelper.getAuthorizationUrlComplete(siteUrl))
        .thenReturn(expectedDiscoveryUrl)
}

// LoginSiteApplicationPasswordViewModel.kt:30-37
fun runApiDiscovery(siteUrl: String) {
    _errorMessage.value = null
    _loadingStateFlow.value = true
    discoveryJob = viewModelScope.launch {
        // ViewModel 不做拼接，只调用 helper
        val discoveryUrl = applicationPasswordLoginHelper
            .getAuthorizationUrlComplete(siteUrl)

        // helper 返回什么，这里就发送什么
        _discoveryURL.send(discoveryUrl)
        _loadingStateFlow.value = false
    }
}

// LoginSiteApplicationPasswordViewModelTest.kt:55-62
viewModel.runApiDiscovery(siteUrl)
verify(applicationPasswordLoginHelper).getAuthorizationUrlComplete(siteUrl)
assertEquals(expectedDiscoveryUrl, collectedUrl)

// ApplicationPasswordLoginHelper.kt:53-57
suspend fun getAuthorizationUrlComplete(siteUrl: String): String =
    try {
        getAuthorizationUrlCompleteInternal(siteUrl)
    } catch (throwable: Throwable) {
        handleAuthenticationDiscoveryError(siteUrl, throwable)
    }

// 注意：上面是真实实现入口，但本测试没有执行到内部发现逻辑

一个容易看漏的点是：测试里的 siteUrl 写成了 "https.example.com"，它本身并不是标准 URL。 但这不影响测试结果，因为这里根本没有走真实网络发现逻辑，返回值完全由 mock 控制。

阅读抓手

先抓这三个结论，再回头看代码会快很多。

1. 这个值是测试常量，不是真实计算结果

真正被断言的值来自 expectedDiscoveryUrl，定义在测试第 41 行， 然后通过 Mockito 的 thenReturn 绑定到 helper 调用。

2. ViewModel 只是透传

runApiDiscovery 只负责清错误、置 loading、调用 helper、发送 flow。 它不校验 URL，也不自己拼接 authorization 地址。

3. 真实 helper 在别处才会做 API discovery

真正的 ApplicationPasswordLoginHelper 会调用 wpLoginClient.apiDiscovery(siteUrl) 并补上参数， 但这一条路径被测试替身隔离掉了。
