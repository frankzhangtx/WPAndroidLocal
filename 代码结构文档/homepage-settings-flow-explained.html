Feature Analysis

WordPress Android 主页设置流程分析

这份文档分析的是站点设置里的“主页设置”弹窗流程，也就是 SiteSettingsFragment 打开 HomepageSettingsDialog 后， 如何加载页面、切换“经典博客 / 静态首页”、选择 Page On Front 和 Page For Posts， 以及最终如何写回站点设置。

入口：WordPress/src/main/java/org/wordpress/android/ui/prefs/SiteSettingsFragment.java
对话框：WordPress/src/main/java/org/wordpress/android/ui/prefs/homepage/HomepageSettingsDialog.kt
状态机：WordPress/src/main/java/org/wordpress/android/ui/prefs/homepage/HomepageSettingsViewModel.kt
保存出口：libs/fluxc/src/main/java/org/wordpress/android/fluxc/store/SiteOptionsStore.kt
我的结论

主页设置不是一个单纯的开关，而是一个带数据加载、校验和保存回写的对话框状态机。 UI 上的关键分支只有两个：classic blog 和 static homepage； 真正决定能不能保存的是页面数据是否加载完成，以及“首页”和“文章页”是否被选成同一页。

先加载页面，再允许保存 静态首页模式需要两个下拉框 同一页不能同时做首页和文章页

入口层

SiteSettingsFragment 在点击“主页设置”偏好项时弹出对话框。

数据层

HomepageSettingsDataLoader 先读本地发布页，再请求远端刷新页面列表。

状态层

HomepageSettingsUiState 负责保存当前模式、页面选择、错误和按钮可用性。

保存层

SiteOptionsStore.updateHomepage() 最终把设置写回站点，并更新本地 SiteModel。

流程总览

主页设置的真实执行顺序

这个流程的核心不是“展示两个选项”，而是把站点当前首页模式、可用页面列表和保存校验绑定在一起， 让用户在一个弹窗内完成配置。

这条链路可以概括成四步：入口打开弹窗、ViewModel 拉取页面并构建 UI 状态、 用户切换模式或下拉选择页面、点击确认后写回站点设置。 对话框在保存成功前不会关闭；如果数据没加载完或者两个页面选成同一个，也会把错误直接显示在弹窗里。

经典博客模式

直接使用 SiteHomepageSettings.Posts，不显示页面下拉框，也不需要选择两个页面。

静态首页模式

需要同时选择 pageOnFront 和 pageForPosts，并且这两个值不能相同。

加载策略

先发出 Loading，再读数据库中已发布页面，随后请求服务器刷新并再次读库。

保存策略

保存成功时关闭弹窗，失败时保留弹窗并写入错误文本，方便用户立即修正。

2. 入口与弹窗

入口来自 SiteSettingsFragment 的偏好点击分支。点击主页设置后，它不会跳到新页面，而是直接通过 HomepageSettingsDialog.newInstance(mSite) 打开一个对话框。 

// SiteSettingsFragment 只负责触发弹窗，不处理主页设置的内部逻辑。
private void showHomepageSettings() {
    HomepageSettingsDialog homepageSettingsDialog =
            HomepageSettingsDialog.Companion.newInstance(mSite);
    homepageSettingsDialog.show(
            getAppCompatActivity().getSupportFragmentManager(),
            "homepage-settings-dialog-tag"
    );
}

// Dialog 先从 arguments / savedInstanceState 取出站点和上次状态，再创建 ViewModel。
viewModel = new ViewModelProvider(this@HomepageSettingsDialog, viewModelFactory)
        [HomepageSettingsViewModel::class.java]
边界说明： 这里说的“主页设置”是站点设置中的首页偏好，不是 My Site 里单独展示的主页预览页。

3. 加载与状态构建

真正的业务状态都在 HomepageSettingsViewModel 里。它先从 SiteStore 找到站点， 再用 HomepageSettingsDataLoader 拉取页面列表，最后把“当前模式 + 当前选中的页面”组装成 HomepageSettingsUiState。 

// ViewModel 初始化时会恢复站点当前的主页设置，并启动页面加载。
fun start(siteId: Int, savedClassicBlogValue: Boolean?, savedPageForPostsId: Long?, savedPageOnFrontId: Long?) {
    dispatcher.register(this)
    launch {
        val siteModel = siteStore.getSiteByLocalId(siteId)
            ?: throw IllegalStateException("SiteModel has to be present")
        val isClassicBlog = savedClassicBlogValue ?: siteModel.showOnFront == ShowOnFront.POSTS.value
        _uiState.value = HomepageSettingsUiState(
            isClassicBlogState = isClassicBlog,
            siteModel = siteModel
        )

        val loadPagesFlow = homepageSettingsDataLoader.loadPages(siteModel)
        withContext(bgDispatcher) {
            loadPagesFlow.filter { loadingResult ->
                loadingResult !is Data || loadingResult.pages.isValid(
                    pageOnFrontId ?: siteModel.pageOnFront,
                    pageForPostsId ?: siteModel.pageForPosts
                )
            }.collect { loadingResult ->
                updateUiState { currentValue ->
                    currentValue.updateWithLoadingResult(
                        loadingResult,
                        pageForPostsId ?: siteModel.pageForPosts,
                        pageOnFrontId ?: siteModel.pageOnFront
                    )
                }
            }
        }
    }
}

数据加载分三段

Loading -> 本地库页面 -> 远端刷新后的页面。这样弹窗先有可用数据，再补最新内容。

页面有效性过滤

如果当前站点保存的首页或文章页不在返回页面列表里，ViewModel 不会把那批数据推进最终 UI。

// 只保留已发布页面，并把加载结果流拆成 Loading / Error / Data。
fun loadPages(siteModel: SiteModel): Flow<LoadingResult> = flow {
    emit(Loading)
    emit(Data(loadPagesFromDb(siteModel)))
    if (pageStore.requestPagesFromServer(siteModel, false).isError) {
        emit(Error(R.string.site_settings_failed_to_load_pages))
    } else {
        emit(Data(loadPagesFromDb(siteModel)))
    }
}

4. 弹窗 UI 如何响应状态

HomepageSettingsDialog 的职责很薄：把状态渲染成单选按钮、下拉框和确认按钮， 并把用户的点击转发给 ViewModel。 

// 经典博客与静态首页之间切换时，只做状态更新，不做保存。
homepageSettingsRadioGroup.setOnCheckedChangeListener { _, checkedId ->
    when (checkedId) {
        R.id.classic_blog -> viewModel.classicBlogSelected()
        R.id.static_homepage -> viewModel.staticHomepageSelected()
    }
}

// 静态首页模式下，需要同时渲染 pageOnFront 和 pageForPosts 两个选择器。
when (uiState.isClassicBlogState) {
    true -> dropdownContainer.visibility = View.GONE
    false -> {
        if (uiState.pageForPostsState != null && uiState.pageOnFrontState != null) {
            dropdownContainer.visibility = View.VISIBLE
            setupDropdownItem(uiState.pageOnFrontState, selectedHomepage, ...)
            setupDropdownItem(uiState.pageForPostsState, selectedPostsPage, ...)
        } else {
            dropdownContainer.visibility = View.GONE
        }
    }
}

下拉菜单不是独立页

它只是 PopupMenu，展开/收起状态也会回写到 HomepageSettingsSelectorUiState。

按钮可用性由校验驱动

确认按钮是否可点，取决于当前 UI 状态是否通过校验，而不是单纯看模式是否切换完毕。

// 选择器会把页面列表转成可显示的文本和选中 ID。
fun selectItem(updatedItemId: Int): HomepageSettingsSelectorUiState {
    val selectedItem = data.find { it.id == updatedItemId }
    val (title, id, isHighlighted) = Builder.buildUiProperties(selectedItem)
    return copy(
        selectedItem = title,
        selectedItemId = id,
        isHighlighted = isHighlighted,
        isExpanded = false
    )
}

5. 保存与回写

点击确认后，ViewModel 先做本地校验，再调用 SiteOptionsStore.updateHomepage()。 成功则关闭弹窗，失败则把错误写回 UI 并保留弹窗。 

// 保存前先进入 loading 状态，避免用户重复点击。
fun onAcceptClicked() {
    val currentUiState = _uiState.value ?: run {
        updateUiStateFromMainThread { it.updateWithError(R.string.site_settings_failed_to_save_homepage_settings) }
        return
    }
    updateUiStateFromMainThread { it.updateWithLoading() }
    launch {
        val siteHomepageSettings = if (currentUiState.isClassicBlogState) {
            SiteHomepageSettings.Posts
        } else {
            val pageForPostsModel = currentUiState.pageForPostsState
            val pageOnFrontModel = currentUiState.pageOnFrontState
            if (pageForPostsModel == null || pageOnFrontModel == null) {
                updateUiState { it.updateWithError(R.string.site_settings_cannot_save_homepage_settings_before_pages_loaded) }
                return@launch
            }
            if (pageForPostsModel == pageOnFrontModel) {
                updateUiState { it.updateWithError(R.string.site_settings_page_for_posts_and_homepage_cannot_be_equal) }
                return@launch
            }
            SiteHomepageSettings.StaticPage(
                pageForPostsId = pageForPostsModel.getSelectedItemRemoteId() ?: 0,
                pageOnFrontId = pageOnFrontModel.getSelectedItemRemoteId() ?: 0
            )
        }

        val updateResult = siteOptionsStore.updateHomepage(currentUiState.siteModel, siteHomepageSettings)
        when (updateResult.isError) {
            true -> updateUiState { it.updateWithError(R.string.site_settings_failed_update_homepage_settings) }
            false -> _dismissDialogEvent.value = Event(Unit)
        }
    }
}

经典博客保存

直接提交 SiteHomepageSettings.Posts，不需要页面 ID。

静态首页保存

会把两个选择器里当前选中的本地页面 ID 转成远端页面 ID，再写给 SiteOptionsStore。

// 存储层会把更新后的结果同步回 SiteModel，并触发站点更新事件。
when (val response = siteHomepageRestClient.updateHomepage(site, homepageSettings)) {
    is Success -> {
        val updatedHomepageSettings = siteHomepageSettingsMapper.map(response.data)
        if (updatedHomepageSettings is StaticPage) {
            site.pageForPosts = updatedHomepageSettings.pageForPostsId
            site.pageOnFront = updatedHomepageSettings.pageOnFrontId
        }
        site.showOnFront = updatedHomepageSettings.showOnFront.value
        dispatcher.dispatch(SiteActionBuilder.newUpdateSiteAction(site))
        HomepageUpdatedPayload(updatedHomepageSettings)
    }
    is Error -> HomepageUpdatedPayload(response.error)
}
校验层在双端都存在： ViewModel 会拦住“两个页面一样”的输入，SiteOptionsStore 也会再做一层保护，避免误写非法参数。

6. 测试如何锁定行为

这个流程有比较完整的单元测试，足以支撑文档里的结论。最关键的是 ViewModel、DataLoader 和 Selector Builder 三组测试。

ViewModel 测试

验证了经典博客 / 静态首页初始化、页面选择、下拉展开、保存成功、保存失败和同页冲突等情况。

DataLoader 测试

验证了只返回已发布页面、先本地后远端两段数据、以及远端错误时会发出错误结果。

Selector Builder 测试

验证了没有选中页面时显示“选择页面”，选中后显示页面标题并高亮。

Mapper 测试

验证了站点模型与后端响应都能正确映射成 Posts 或 StaticPage。

这意味着什么： 这条链路的行为不是靠猜，而是被测试固定住了。文档里写的“先加载页面、同页不能保存、成功才 dismiss”都有测试支撑。
阅读指南

看源码时优先盯住的点

这些点决定了主页设置是否能正确展示、选择和保存。

1. 入口只负责打开

SiteSettingsFragment 不做业务，真正逻辑都在对话框和 ViewModel。

2. 默认模式怎么来的

如果没有保存过临时状态，就从站点当前的 showOnFront 还原。

3. 页面列表从哪来

HomepageSettingsDataLoader 过滤的是已发布页面，不会把草稿或其他状态混进来。

4. 什么时候能点保存

只有没有错误且校验通过时，确认按钮才会启用。

5. 为何要双重校验

ViewModel 和 Store 都检查“首页和文章页不能相同”，避免非法写回。

6. 成功后发生什么

更新成功后，弹窗关闭，站点模型更新，相关观察者会收到站点变更事件。
