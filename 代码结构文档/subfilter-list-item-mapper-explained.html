SubfilterListItemMapper 的用途、界面位置与调用时机

这个类位于 Reader 子筛选链路里，但它的职责非常窄：它并不负责“加载筛选列表”或“切换页面内容”，而是负责把当前选中的 SubfilterListItem 在 Bundle 可保存的 JSON 结构和运行时对象之间来回转换。换句话说，它更像一个 “筛选项状态编解码器”，用于保存与恢复筛选状态。

主源码：WordPress/src/main/java/org/wordpress/android/ui/reader/subfilter/SubfilterListItemMapper.kt
关键调用方：SubFilterViewModel、ReaderFragment、ReaderPostListFragment
界面范围：Reader 主界面顶部筛选组 + 底部筛选弹层
核心职责：状态保存/恢复
不是：筛选列表加载器
不是：Reader 模式切换器
直接依赖：ReaderBlogTableWrapper、ReaderUtilsWrapper

先给结论

先区分“筛选 UI 在哪里出现”和“mapper 真正何时被调用”。

1. 它的职责很窄：只做状态对象与 JSON 之间的映射

toJson() 把当前选中的 SubfilterListItem 压缩成一个轻量 JSON； fromJson() 再把这个 JSON 还原成 SiteAll、Site 或 Tag。

2. 它不会在“每次点开筛选弹层”时都被调用

用户点击 Reader 顶部的筛选按钮时，真正发生的是 ReaderFragment.tryOpenFilterList() -> SubFilterViewModel.onSubFiltersListButtonClicked() -> 显示 SubfilterBottomSheetFragment。 这一段主要是 UI 展示，不经过 mapper。

3. 它主要在“保存状态”和“恢复状态”时出现

当前代码里最明确的保存入口是 ReaderPostListFragment.onSaveInstanceState()， 它会调用 SubFilterViewModel.onSaveInstanceState()，再间接触发 SubfilterListItemMapper.toJson()。恢复时则由 SubFilterViewModel.start() 读取 current_subfilter_json 并调用 fromJson()。

阅读抓手

看这个类时，最重要的是分清职责边界。

核心输入

json、SubfilterListItem、以及恢复对象时需要的点击回调与选中态。

核心输出

运行时的 SiteAll / Site / Tag，或可落入 Bundle 的 JSON 字符串。

真正意义

它让 Reader 的“当前筛选项”在界面重建后还能重新被还原出来，而不是重新回到默认状态。

关键风险

现有实现对未知 type 会直接抛出 IllegalArgumentException； 这说明它目前偏向“严格恢复”，不是完全兜底的容错实现。

它出现在哪个界面

它服务的是 Reader 顶部筛选体验，而不是独立页面。

界面 / 组件 代码位置 用户能看到什么 和 mapper 的关系
Reader 主界面 ReaderFragment 顶部栏里有 Blog / Tag 的筛选入口，点击后可打开筛选面板 负责触发筛选 UI；通常不是 mapper 的直接调用点
筛选底部弹层 SubfilterBottomSheetFragment 用户会看到 Sites / Tags 列表，以及“管理订阅”入口 消费 SubFilterViewModel 的状态；不是直接序列化/反序列化位置
Reader 内容列表 ReaderPostListFragment 根据当前选中的子筛选项切换博客预览、标签流或默认流 这里是当前代码中最明确的保存状态入口，会触发 toJson()
Tags Feed 变体界面 ReaderTagsFeedFragment 当当前筛选项是 Tag 时，会显示对应标签的文章列表 会复用同一个 SubFilterViewModel，但当前显式保存入口不在这里

什么情况下会调用到这个类

最值得注意的一点：打开筛选面板 != 调用 mapper。

场景 是否会调用 mapper 调用方法 说明
用户点击 Reader 顶部 Blog / Tag 筛选按钮 否 无 只会走 ReaderFragment.tryOpenFilterList() 和底部弹层展示逻辑
用户在底部弹层里选择某个站点或标签 通常否 无 这一步主要是更新内存中的 currentSubFilter，然后驱动 readerModeInfo
页面即将保存状态，例如 Fragment 重建前 是 toJson() 由 ReaderPostListFragment.onSaveInstanceState() -> SubFilterViewModel.onSaveInstanceState() 间接触发
页面重建后恢复之前的筛选项 是 fromJson() 由 SubFilterViewModel.start(..., savedInstanceState) 读取 current_subfilter_json 后触发
这也是为什么这个类的名字里叫 Mapper：它更像是“状态结构转换器”，而不是“业务流程主控类”。

带中文注释的代码片段

片段 1：类本体，说明它到底怎么做对象编解码。

private data class MappedSubfilterListItem(
    val type: Int,
    var feedId: Long = 0,
    var blogId: Long = 0,
    var tagSlug: String = "",
    var tagType: Int = 0
)

class SubfilterListItemMapper @Inject constructor(
    private val readerUtilsWrapper: ReaderUtilsWrapper,
    private val readerBlogTableWrapper: ReaderBlogTableWrapper
) {
    // [说明] fromJson: 把 Bundle 里的轻量 JSON 还原成真正可用的筛选项对象。
    fun fromJson(
        json: String,
        onClickAction: (filter: SubfilterListItem) -> Unit,
        isSelected: Boolean
    ): SubfilterListItem {
        val mappedItem = if (json.isEmpty()) {
            // [说明] 没有保存值时，默认回到“全部内容”筛选。
            MappedSubfilterListItem(type = SubfilterListItem.ItemType.SITE_ALL.value)
        } else {
            Gson().fromJson(json, MappedSubfilterListItem::class.java)
        }

        return when (mappedItem.type) {
            SubfilterListItem.ItemType.SITE.value -> {
                val blogInfo: ReaderBlog? = if (mappedItem.blogId != 0L) {
                    // [说明] blogId 优先表示订阅站点。
                    readerBlogTableWrapper.getBlogInfo(mappedItem.blogId)
                } else if (mappedItem.feedId != 0L) {
                    // [说明] feedId 则表示 feed 订阅。
                    readerBlogTableWrapper.getFeedInfo(mappedItem.feedId)
                } else null

                blogInfo?.let {
                    SubfilterListItem.Site(
                        blog = blogInfo,
                        onClickAction = onClickAction,
                        isSelected = isSelected
                    )
                } ?: SubfilterListItem.SiteAll(onClickAction = onClickAction, isSelected = isSelected)
            }

            SubfilterListItem.ItemType.TAG.value -> {
                if (mappedItem.tagSlug.isNotEmpty()) {
                    // [说明] 标签恢复需要 slug + tagType，真正的 ReaderTag 由工具类再查出来。
                    val tag = readerUtilsWrapper.getTagFromTagName(
                        mappedItem.tagSlug,
                        ReaderTagType.fromInt(mappedItem.tagType)
                    )
                    SubfilterListItem.Tag(
                        tag = tag,
                        onClickAction = onClickAction,
                        isSelected = isSelected
                    )
                } else {
                    SubfilterListItem.SiteAll(onClickAction = onClickAction, isSelected = isSelected)
                }
            }

            SubfilterListItem.ItemType.SITE_ALL.value -> {
                // [说明] 这是“清空筛选 / 查看全部”状态。
                SubfilterListItem.SiteAll(
                    onClickAction = onClickAction,
                    isSelected = isSelected
                )
            }

            else -> throw IllegalArgumentException(
                "fromJson > Unexpected Subfilter type $mappedItem.type"
            )
        }
    }

    // [说明] toJson: 把当前筛选项压缩成最小必要字段，方便写进 Bundle。
    fun toJson(item: SubfilterListItem): String {
        val mappedItem = MappedSubfilterListItem(type = item.type.value)

        when (item) {
            is SubfilterListItem.Site -> {
                mappedItem.feedId = item.blog.feedId
                mappedItem.blogId = item.blog.blogId
            }
            is SubfilterListItem.Tag -> {
                mappedItem.tagSlug = item.tag.tagSlug
                mappedItem.tagType = item.tag.tagType.toInt()
            }
            is SubfilterListItem.Divider,
            is SubfilterListItem.SectionTitle,
            is SubfilterListItem.SiteAll -> Unit
        }

        return Gson().toJson(mappedItem)
    }
}
这个类故意不保存完整的 ReaderBlog 或 ReaderTag 对象，只保存能够“重新找回”它们的最小键值。 这说明它的目标是轻量持久化，而不是做深拷贝缓存。

片段 2：它被谁包起来使用

片段 2：调用链告诉你它不是交互主角，而是状态中转站。

// ReaderFragment: 用户点顶部筛选按钮，只是打开底部筛选面板。
private fun tryOpenFilterList(type: ReaderFilterType) {
    val viewModel = getSubFilterViewModel() ?: return
    val category = when (type) {
        ReaderFilterType.BLOG -> SubfilterCategory.SITES
        ReaderFilterType.TAG -> SubfilterCategory.TAGS
    }
    viewModel.onSubFiltersListButtonClicked(category)
}

// SubFilterViewModel: 真正的保存入口，间接调用 mapper.toJson。
private fun getCurrentSubfilterJson(): String {
    return subfilterListItemMapper.toJson(getCurrentSubfilterValue())
}

fun onSaveInstanceState(outState: Bundle) {
    outState.putString(ARG_CURRENT_SUBFILTER_JSON, getCurrentSubfilterJson())
    outState.putBoolean(ARG_IS_FIRST_LOAD, isFirstLoad)
}

// SubFilterViewModel.start: 重建时，如果 Bundle 里有 JSON，就用 mapper.fromJson 还原。
fun start(mTagFragmentStartedWith: ReaderTag?, tag: ReaderTag?, savedInstanceState: Bundle?) {
    var subfilterJson: String? = null

    savedInstanceState?.let {
        isFirstLoad = it.getBoolean(ARG_IS_FIRST_LOAD)
        subfilterJson = it.getString(ARG_CURRENT_SUBFILTER_JSON)
    }

    tag?.let {
        val currentSubfilter = subfilterJson?.let { json ->
            subfilterListItemMapper.fromJson(
                json = json,
                onClickAction = ::onSubfilterClicked,
                isSelected = true
            )
        }
        updateSubfilter(currentSubfilter ?: getCurrentSubfilterValue())
    }
}

// ReaderPostListFragment: 当前代码里最明确的“保存状态”触发点。
if (isFilterableScreen && subFilterViewModel != null) {
    subFilterViewModel!!.onSaveInstanceState(outState)
}

// ReaderTagsFeedFragment: 会观察 currentSubFilter，并据此显示标签文章流。
subFilterViewModel.currentSubFilter.observe(viewLifecycleOwner) { subFilter ->
    if (subFilter is SubfilterListItem.Tag) {
        showTagPostList(subFilter.tag)
    } else {
        hideTagPostList()
    }
}
这段调用链说明：用户交互时主要操作的是 ViewModel 与 UI；mapper 只在需要跨重建保存选择结果时出场。

执行流程图

图里分成两条线：日常交互线，以及真正会调用 mapper 的保存/恢复线。

读图方式：上半部分是“用户正在操作筛选 UI”的实时交互，这条线里 SubfilterListItemMapper 通常不会出场； 下半部分是“界面需要跨重建保留当前筛选项”的保存/恢复流程，这才是这个类最核心的调用场景。当前代码里， 显式的保存入口在 ReaderPostListFragment.onSaveInstanceState()，而恢复逻辑集中在 SubFilterViewModel.start()。
