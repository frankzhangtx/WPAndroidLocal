Feature Analysis

WordPress Android 站点标签管理流程分析

这份文档分析的是站点设置里的标签管理流程，也就是 SiteSettingsFragment 打开 SiteSettingsTagListActivity 后，如何加载标签、搜索标签、进入标签详情、保存修改和删除标签。 它和文章编辑里的标签选择不同，这里管理的是站点级别的 TermModel 标签集合。

入口：WordPress/src/main/java/org/wordpress/android/ui/prefs/SiteSettingsFragment.java
列表页：WordPress/src/main/java/org/wordpress/android/ui/prefs/SiteSettingsTagListActivity.java
详情页：WordPress/src/main/java/org/wordpress/android/ui/prefs/SiteSettingsTagDetailFragment.java
数据源：org.wordpress.android.fluxc.store.TaxonomyStore
我的结论

这条链路的核心是一个“列表页 + 详情页”的标签编辑器。列表页负责加载、搜索和进入编辑， 详情页负责输入、删除和判断是否有改动；真正的保存与删除都通过 TaxonomyActionBuilder 派发到 TaxonomyStore，再由事件回调把界面收口。

站点标签不是文章标签 保存前会检查是否重名 修改成功后自动回到列表
阅读顺序

先看入口如何打开列表页，再看列表页如何加载与筛选标签，随后看详情页如何编辑并提交修改。

入口层

SiteSettingsFragment 点击标签设置后启动 SiteSettingsTagListActivity。

列表层

SiteSettingsTagListActivity 从 TaxonomyStore 读取标签并支持搜索过滤。

详情层

SiteSettingsTagDetailFragment 负责名称、描述、是否新标签和删除菜单。

提交层

TaxonomyActionBuilder + TaxonomyStore 完成标签新增、更新和删除。

流程总览

站点标签管理的真实执行顺序

这个流程不是单纯“点开标签列表看一眼”，而是一个带数据刷新、详情编辑和后端事件回调的站点级管理页面。

你可以把它理解成四步：入口打开列表页、列表页从 TaxonomyStore 读取标签、 点击某个标签或 FAB 进入详情页、保存/删除后靠 taxonomy 事件收口到列表页。 列表页本身也承担搜索、空态、返回、进度提示和 FAB 动画控制。

列表页职责

负责加载标签、排序、搜索、打开详情页、处理保存/删除后的列表刷新。

详情页职责

负责编辑标签名称和描述，处理新建标签的 slug，提供删除菜单。

保存行为

新标签会先检查是否重名，已有标签则直接 push 到 taxonomy 层。

删除行为

删除前会确认网络可用，再弹出确认框，确认后派发删除 action。

2. 入口与页面结构

入口在 SiteSettingsFragment 的偏好点击分支里。点击标签设置项时，它直接调用 SiteSettingsTagListActivity.showTagList(getActivity(), mSite)，把站点对象传给独立 Activity。 这意味着标签管理是一个单独的站点设置页面，而不是在原页面里嵌入一个对话框。 

// SiteSettingsFragment 只负责把“标签设置”跳转出去。
else if (preference == mTagsPref) {
    SiteSettingsTagListActivity.showTagList(getActivity(), mSite);
}

// Activity 的静态入口只带站点对象，不携带别的复杂状态。
public static void showTagList(@NonNull Context context, @NonNull SiteModel site) {
    Intent intent = new Intent(context, SiteSettingsTagListActivity.class);
    intent.putExtra(WordPress.SITE, site);
    context.startActivity(intent);
}
页面结构： SiteSettingsTagListActivity 是主容器，里面有列表、FAB、搜索框和空态视图； SiteSettingsTagDetailFragment 则以 fragment 叠加到列表页上，形成“列表 + 详情”的编辑体验。

3. 标签如何加载与搜索

列表页在首次创建时会从 TaxonomyStore 取站点标签，并触发一次 TaxonomyActionBuilder.newFetchTagsAction(mSite)，让远端结果回来后刷新列表。 标签展示按名称做忽略大小写排序，并支持搜索过滤。 

// 列表页创建时，先读本地缓存，再拉远端标签。
loadTags();
if (savedInstanceState == null) {
    mDispatcher.dispatch(TaxonomyActionBuilder.newFetchTagsAction(mSite));
}

// loadTags() 会从 TaxonomyStore 取站点标签并按名称排序。
private void loadTags() {
    List<TermModel> tags = mTaxonomyStore.getTagsForSite(mSite);
    Collections.sort(tags, (t1, t2) -> StringUtils.compareIgnoreCase(t1.getName(), t2.getName()));
    mAdapter = new TagListAdapter(tags);
    mRecycler.setAdapter(mAdapter);
}

搜索不是独立数据源

搜索只是对 mAllTags 做本地过滤，不会再次请求网络。

空态会动态切换

搜索时如果没有结果，空态会变成“搜索无结果”；非搜索空态则展示新增按钮。

// 过滤后会刷新列表，并据搜索状态切换空态展示。
public void filter(final String text) {
    mFilteredTags.clear();
    if (TextUtils.isEmpty(text)) {
        mFilteredTags.addAll(mAllTags);
    } else {
        for (TermModel tag : mAllTags) {
            if (tag.getName().toLowerCase(Locale.getDefault()).contains(text.toLowerCase(Locale.getDefault()))) {
                mFilteredTags.add(tag);
            }
        }
    }
    notifyDataSetChanged();
    showActionableEmptyViewForSearch(mIsSearching && mFilteredTags.isEmpty());
}

4. 标签详情页如何编辑

点列表中的标签，或者点 FAB 新增标签，都会打开 SiteSettingsTagDetailFragment。 这个 fragment 通过 TermModel 初始化输入框，区分“编辑已有标签”和“创建新标签”两种模式。 

// 详情页的入口允许传入已有标签，也允许传 null 创建新标签。
public static SiteSettingsTagDetailFragment newInstance(@Nullable TermModel term) {
    if (term == null) {
        args.putBoolean(ARGS_IS_NEW_TERM, true);
        term = new TermModel(TaxonomyStore.DEFAULT_TAXONOMY_TAG);
    }
    args.putSerializable(ARGS_TERM, term);
    fragment.setArguments(args);
    return fragment;
}

// 详情页会根据模式决定标题、输入内容和是否展示删除菜单。
if (mIsNewTerm) {
    requireActivity().setTitle(R.string.add_new_tag);
} else {
    requireActivity().setTitle(mTerm.getName());
}

// 新标签会在保存时自动生成 slug。
if (mIsNewTerm) {
    mTerm.setSlug(sanitizeWithDashes(thisName));
}

是否有改动

hasChanges() 会判断新建标签是否输入了名字，编辑标签则比较名称和描述是否变化。

删除菜单只对旧标签显示

新建标签没有可删除的远端对象，所以 trash 菜单会被隐藏。

5. 保存、删除与事件收口

保存和删除都不是在 UI 层直接改数据库，而是通过 taxonomy action 派发给后端，再由 OnTaxonomyChanged 事件回调把页面状态收口。 

// 返回键在详情页打开时有特殊语义：有改动就先保存，没有改动就直接回列表。
if (fragment != null && fragment.hasChanges()) {
    saveTag(fragment.getTerm(), fragment.isNewTerm());
} else {
    hideDetailFragment();
    loadTags();
}

// 新标签会先做重名检查，再 dispatch push action。
private void saveTag(@NonNull TermModel term, boolean isNewTerm) {
    if (isNewTerm && tagExists(term.getName())) {
        ToastUtils.showToast(this, R.string.error_tag_exists);
        return;
    }
    showProgressDialog(R.string.dlg_saving_tag);
    Action action = TaxonomyActionBuilder.newPushTermAction(
            new TaxonomyStore.RemoteTermPayload(term, mSite)
    );
    mDispatcher.dispatch(action);
}

删除前要确认网络

onRequestDeleteTag() 会先检查网络，网络可用才弹出确认删除框。

事件收口在列表页

保存/删除成功后，列表页隐藏进度条、关闭详情页，并重新加载标签列表。

// taxonomy 事件是这条链路的收口点。
@Subscribe(threadMode = ThreadMode.MAIN)
public void onTaxonomyChanged(OnTaxonomyChanged event) {
    switch (event.causeOfChange) {
        case FETCH_TAGS:
            if (!event.isError()) {
                loadTags();
            }
            break;
        case REMOVE_TERM:
        case UPDATE_TERM:
            hideProgressDialog();
            hideDetailFragment();
            if (!event.isError()) {
                loadTags();
            }
            break;
    }
}
流程收尾： 保存成功或删除成功后，界面都回到列表页并刷新数据；失败时保留当前详情页，让用户继续修改或重试。

6. 测试与风险点

这条链路没有找到专门的本地单元测试文件，但代码里已经有几个明确的行为约束，文档应当把它们当作事实前提： 只有新标签才做重名检查，删除只对旧标签可用，保存和删除都依赖 taxonomy 事件完成界面收口。

值得关注的风险

如果 taxonomy 事件没有正确到达，列表页会停留在进度态或不会自动刷新。

交互上的约束

搜索状态下空态、详情态和 FAB 显示逻辑有联动，改动时容易误伤列表可用性。

文档边界： 这里解释的是站点设置里的标签管理，不包括文章编辑里的标签选择，也不包括 Reader 里的标签功能。
阅读指南

看源码时优先盯住的点

这些点决定了标签管理页是否能正确打开、编辑、保存和刷新。

1. 入口是谁触发的

SiteSettingsFragment 只做跳转，真正的业务从列表页开始。

2. 标签从哪来

列表页先读 TaxonomyStore，再发起 FETCH_TAGS 刷新。

3. 详情页如何区分新旧

通过 ARGS_IS_NEW_TERM 和默认 TermModel 判断是否是新建。

4. 保存前有没有校验

新标签会检查是否重名；返回键在有改动时也会触发保存。

5. 删除是否会直接执行

不会。先网络检查，再确认对话框，最后 dispatch 删除 action。

6. 成功后怎么收口

事件回调会关闭详情页、隐藏进度条，并重新载入标签列表。
