1. 架构概览

本工程采用 FluxC + MVVM 架构管理登录流程。整体分为三层：

  • UI 层：LoginActivity / Fragments / Compose Screens + ViewModels
  • 业务逻辑层：WPcomLoginHelper / ApplicationPasswordLoginHelper / LoginFlow 枚举
  • 数据层（FluxC）：AccountStore / Authenticator / AccessToken / SiteStore

数据流向：UI Event → ViewModel/Helper → FluxC Action → Dispatcher → Store → LiveData/EventBus → UI 更新

3. WordPress.com OAuth 登录流程

详细步骤说明

  1. 启动 LoginActivity：WPMainActivity 检测到未登录状态，通过 ActivityLauncher 启动 LoginActivity（singleTop 模式）
  2. 展示 Prologue 页：LoginPrologueRevampedFragment 显示 "Continue with WordPress.com" 和 "Enter your site address" 两个入口
  3. 发起 OAuth 授权：点击 "Continue with WordPress.com" 后，WPcomLoginHelper 构建授权 URI 并预加载 Custom Tabs，然后打开浏览器
  4. 用户认证：用户在 WordPress.com 的 Custom Tabs 中输入账号密码完成认证
  5. 回调处理：认证成功后，Custom Tabs 通过 Deep Link (<scheme>://wpcom-authorize?code=...) 回调到 LoginActivity.onNewIntent()
  6. Token 交换：WPcomLoginClient 将 authorization code 通过 POST 请求换取 access_token
  7. 存储 Token：AccountStore 将 access_token 持久化到 SharedPreferences（通过 AccessToken 类）
  8. 完成登录：获取账户详情和站点列表后，导航至 WPMainActivity

4. 自托管站点 Application Password 登录流程

详细步骤说明

  1. 输入站点地址：在 LoginSiteApplicationPasswordFragment（Compose UI）中输入自托管 WordPress 站点 URL
  2. API 发现：WpLoginClient.apiDiscovery() 请求站点，发现 WP REST API 根路径和 Application Password 授权端点
  3. 构建授权 URL：将发现的 authorize-application.php URL 附加 app_name（如 "WordPress on Pixel"）和 success_url 参数
  4. 用户授权：在 Custom Tabs 中打开站点后台授权页，用户登录站点后台并批准应用密码创建
  5. 回调处理：授权成功后，通过 Deep Link (<scheme>://app-pass-authorize) 回调至 ApplicationPasswordLoginActivity
  6. 存储凭据：解析 URI 获取 site_url、user_login、password，存入 SiteModel 的 apiRestUsernamePlain / apiRestPasswordPlain 字段
  7. 获取站点：通过 SiteStore 获取站点完整信息，导航至主界面

5. Magic Link 登录流程

详细步骤说明

  1. 点击 Magic Link：用户在邮箱中点击 Magic Link，Android 系统根据 Deep Link scheme 打开 LoginMagicLinkInterceptActivity
  2. 转发处理：LoginMagicLinkInterceptActivity 设置标记后，将 Intent 转发至 WPMainActivity
  3. 提取 Token：WPMainActivity 从 Intent 的 URI data 中解析出 access_token
  4. 存储 Token：通过 AccountStore.updateAccessToken() 持久化 Token
  5. 初始化：onAuthenticationChanged() 事件触发，完成站点初始化

6. Jetpack 特有流程

Jetpack 特有逻辑

  • 迁移流程：Jetpack App 首次启动时，检测是否可从同设备已安装的 WordPress App 迁移登录数据（SharedLoginData / JetpackSharedLoginFlag）
  • 无 Jetpack 站点处理：WP.com 登录成功后，如果用户账号下没有 Jetpack 连接的站点，显示 LoginNoSitesFragment（可查看安装指引或切换账号）
  • 站点检查错误：连接 Jetpack 统计等功能时，如果站点未安装 Jetpack，显示 LoginSiteCheckErrorFragment

8. 登录成功后处理

WP.com 登录成功后

  1. accountStore.updateAccessToken(token) → 触发 OnAuthenticationChanged
  2. loggedInAndFinish() 被调用，设置 doLoginUpdate=true
  3. Dispatch AccountAction.FETCH_ACCOUNT → 获取用户账户信息
  4. onAccountChanged() → Dispatch SiteAction.FETCH_SITES → 获取站点列表
  5. onSiteChanged() → finishLoginAfterSitesLoaded()
  6. 启动后登录服务：Reader Tags 同步、Notifications 注册
  7. ActivityLauncher.showMainActivity() 并 finish()

自托管登录成功后

  1. 凭据存入 SiteModel
  2. SiteStore.fetchSitesXmlRpcFromApplicationPassword() 获取站点详情
  3. 导航至 WPMainActivity，设置 ARG_SELECTED_SITE 为新站点 ID
