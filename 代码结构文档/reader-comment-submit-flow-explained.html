Feature Analysis

WordPress Android 发表评论流程分析

本文聚焦 Reader 里的文章评论与回复评论流程，不包含后台“评论管理”页面。 主链路是：打开评论页 -> 进入评论输入/回复模式 -> 本地生成“假评论”占位 -> 调用 ReaderCommentActions 发起网络请求 -> 成功后替换为真实评论，失败后恢复输入并删除占位。

主入口：WordPress/src/main/java/org/wordpress/android/ui/reader/ReaderCommentListActivity.kt
提交动作：WordPress/src/main/java/org/wordpress/android/ui/reader/actions/ReaderCommentActions.java
列表刷新：WordPress/src/main/java/org/wordpress/android/ui/reader/adapters/ReaderCommentAdapter.java
全屏编辑：WordPress/src/main/java/org/wordpress/android/ui/CommentFullScreenDialogFragment.kt
这条链路的核心特征

评论提交采用“乐观更新”模式。用户点发送后，UI 会先插入一条本地假评论并高亮显示， 这样列表不会卡在等待态；等网络请求返回后，再用真实评论替换占位，或者在失败时把草稿文本还回输入框。

先插入假评论，再异步请求 失败会恢复输入内容 回复评论会走父评论子回复接口

输入门禁

只有有登录态且文章评论开放时，评论输入框和发送按钮才会显示；否则会隐藏或置灰。

乐观占位

发送后先生成 fakeCommentId，把本地评论插入列表，避免用户感觉“没反应”。

回复模式

回复某条评论时会高亮目标评论并切换 hint，回退键在空文本情况下会取消回复目标。

结果处理

成功后替换为服务器返回的真实评论并累计评论数，失败则恢复文本、删除占位并 toast 提示。

流程总览

发表评论的真实执行顺序

这不是一个纯粹的“输入框提交”流程，而是一个以 Reader 页面为入口、以本地缓存为中间层、再把成功结果写回列表的乐观更新流程。

1. 入口与输入条件

评论页在 ReaderCommentListActivity 中初始化。loadPost() 会先检查是否拿到了帖子， 再根据账号登录状态和 readerPost.isCommentsOpen 决定评论输入区是否可见。 

// 只有已登录且评论开放时，输入框和发送按钮才可用。
private fun loadPost(): Boolean {
    readerPost = ReaderPostTable.getBlogPost(blogId, postId, false)
    if (readerPost == null) {
        return false
    }

    if (!accountStore.hasAccessToken()) {
        boxBinding.layoutContainer.visibility = View.GONE
        showCommentsClosedMessage(false)
    } else if (readerPost!!.isCommentsOpen) {
        boxBinding.layoutContainer.visibility = View.VISIBLE
        showCommentsClosedMessage(false)
        boxBinding.editComment.setOnEditorActionListener { _, actionId, _ ->
            if (actionId == EditorInfo.IME_ACTION_DONE || actionId == EditorInfo.IME_ACTION_SEND) {
                submitComment()
            }
            false
        }
        boxBinding.btnSubmitReply.setOnClickListener { submitComment() }
    } else {
        boxBinding.layoutContainer.visibility = View.GONE
        boxBinding.editComment.isEnabled = false
        showCommentsClosedMessage(true)
    }

    return true
}

没有登录态

如果 accountStore.hasAccessToken() 为假，评论区直接隐藏，说明当前用户不能发表评论。

评论已关闭

如果文章关闭评论，输入框会禁用并显示“评论关闭”提示，不会进入提交逻辑。

2. 回复模式与全屏编辑

评论页不仅能直接发到文章下，还能对某条评论进行回复。回复时，replyToCommentId 会被切换， 列表中的目标评论会被高亮，输入框 hint 也会从“评论文章”变成“评论某条评论”。 

// 点击回复按钮后，当前目标评论被高亮，输入框 hint 也随之变化。
private fun setReplyToCommentId(id: Long, doFocus: Boolean) {
    replyToCommentId = if (replyToCommentId == id) {
        0
    } else {
        id
    }

    boxBinding.editComment.setHint(
        if (replyToCommentId == 0L) R.string.reader_hint_comment_on_post
        else R.string.reader_hint_comment_on_comment
    )

    if (doFocus) {
        boxBinding.editComment.postDelayed({
            ActivityUtils.showKeyboard(boxBinding.editComment)
            setupReplyToComment()
        }, FOCUS_DELAY_MS)
    } else {
        setupReplyToComment()
    }
}

页面上的“展开”按钮会打开全屏评论编辑器。这个编辑器只是输入容器，不直接提交；它会把文本和选区回传给 Activity， 再由 Activity 决定是继续编辑还是马上发送。 

// 全屏编辑器返回两种结果：collapse 只恢复文本，confirm 会直接触发提交。
override fun onCollapse(result: Bundle?) {
    if (result != null) {
        boxBinding.editComment.setText(result.getString(CommentFullScreenDialogFragment.RESULT_REPLY))
        boxBinding.editComment.setSelection(
            result.getInt(CommentFullScreenDialogFragment.RESULT_SELECTION_START),
            result.getInt(CommentFullScreenDialogFragment.RESULT_SELECTION_END)
        )
        boxBinding.editComment.requestFocus()
    }
}

override fun onConfirm(result: Bundle?) {
    if (result != null) {
        boxBinding.editComment.setText(result.getString(CommentFullScreenDialogFragment.RESULT_REPLY))
        submitComment()
    }
}

回复时的列表反馈

ReaderCommentAdapter.setReplyTargetComment() 会把目标评论标记出来，帮助用户确认自己在回复哪一层。

空文本回退

在回复模式下，如果用户在输入框里按 back 且文本为空，回复目标会被自动重置为文章本身。

3. 提交评论的主逻辑

发表评论真正开始于 submitComment()。这个方法先做本地校验，再做埋点，然后立即在本地制造一条“假评论”占位， 最后把真正的网络请求交给 ReaderCommentActions.submitPostComment()。 

// 提交前先校验文本和网络；通过后立即生成 fakeCommentId 做乐观更新。
private fun submitComment() {
    val commentText = EditTextUtils.getText(boxBinding.editComment)
    if (TextUtils.isEmpty(commentText)) {
        return
    }

    if (!NetworkUtils.checkConnection(this)) {
        return
    }

    if (replyToCommentId != 0L) {
        readerTracker.trackPost(AnalyticsTracker.Stat.READER_ARTICLE_COMMENT_REPLIED_TO, readerPost)
    } else {
        readerTracker.trackPost(AnalyticsTracker.Stat.READER_ARTICLE_COMMENTED_ON, readerPost)
    }

    boxBinding.btnSubmitReply.isEnabled = false
    boxBinding.editComment.isEnabled = false
    isSubmittingComment = true

    val fakeCommentId = ReaderCommentActions.generateFakeCommentId()
    val wpComUserId = accountStore.account.userId
    val actionListener = getCommentActionListener(fakeCommentId, commentText)
    val newComment = ReaderCommentActions.submitPostComment(
        readerPost,
        fakeCommentId,
        commentText,
        replyToCommentId,
        actionListener,
        wpComUserId
    )

    if (newComment != null) {
        boxBinding.editComment.text = null
        getCommentAdapter().setHighlightCommentId(newComment.commentId, true)
        getCommentAdapter().setReplyTargetComment(0)
        getCommentAdapter().addComment(newComment)
        scrollToCommentId(fakeCommentId)
        checkEmptyView()
    }
}

为什么要先禁用输入框

这是为了防止用户在请求未完成前重复发送。发送按钮和输入框被禁用后，提交状态由 isSubmittingComment 维持。

为什么要先插入假评论

评论一旦发出，用户就能立刻看到自己的内容出现在列表里，体验更像即时发布，而不是“点击后等待一片空白”。

4. ReaderCommentActions 的乐观更新

ReaderCommentActions.submitPostComment() 才是实际发请求的地方。它会先构造本地 comment 对象并写入本地表， 再根据是否是回复，选择不同的 REST 路径。成功后删除假评论并换成服务端返回的真实评论，失败后则删掉假评论并回调失败。 

// ReaderCommentActions 先写本地缓存，再发网络请求。
public static ReaderComment submitPostComment(
        final @Nullable ReaderPost post,
        final long fakeCommentId,
        final String commentText,
        final long replyToCommentId,
        final ReaderActions.CommentActionListener actionListener,
        final long wpComUserId) {
    if (post == null || TextUtils.isEmpty(commentText)) {
        return null;
    }

    final int pageNumber = replyToCommentId != 0
            ? ReaderCommentTable.getPageNumberForComment(post.blogId, post.postId, replyToCommentId)
            : ReaderCommentTable.getLastPageNumberForPost(post.blogId, post.postId);

    ReaderComment newComment = new ReaderComment();
    newComment.commentId = fakeCommentId;
    newComment.postId = post.postId;
    newComment.blogId = post.blogId;
    newComment.parentId = replyToCommentId;
    newComment.pageNumber = pageNumber;
    newComment.setStatus(CommentStatus.APPROVED.toString());
    newComment.setText(commentText);
    ReaderCommentTable.addOrUpdateComment(newComment);

    final String path = replyToCommentId == 0
            ? "sites/" + post.blogId + "/posts/" + post.postId + "/replies/new"
            : "sites/" + post.blogId + "/comments/" + replyToCommentId + "/replies/new";

    WordPress.getRestClientUtilsV1_1().post(path, params, null, listener, errorListener);
    return newComment;
}

普通评论和回复评论的差别

普通评论走 /posts/{postId}/replies/new；回复某条评论走 /comments/{commentId}/replies/new。

为什么叫“假评论”

它只是一个本地占位对象，commentId 用当前时间生成，真实数据回来后会被删除并替换。

5. 列表如何展示成功或失败

评论列表的刷新由 ReaderCommentAdapter 完成。这里有三条关键路径： 顶层评论直接追加，回复评论需要重新整理层级；成功时替换假评论并刷新帖子状态，失败时恢复文本并删除假评论。 

// 顶层评论直接追加；回复评论需要重新层级化列表。
public void addComment(ReaderComment comment) {
    if (comment == null) {
        return;
    }

    if (comment.parentId == 0) {
        mComments.add(comment);
        notifyDataSetChanged();
    } else {
        refreshComments();
    }
}

public void replaceComment(long commentId, ReaderComment comment) {
    int positionOfTargetComment = positionOfCommentId(comment.commentId);
    if (positionOfTargetComment == -1) {
        int position = positionOfCommentId(commentId);
        if (position > -1 && mComments.replaceComment(commentId, comment)) {
            notifyItemChanged(position);
        }
    } else {
        removeComment(commentId);
    }
}
// 成功后：去掉假评论，替换为真实评论，增加评论总数；失败后：恢复文本并移除占位。
private fun getCommentActionListener(fakeCommentId: Long, commentText: String): CommentActionListener {
    return CommentActionListener { succeeded: Boolean, newComment: ReaderComment? ->
        if (isFinishing) {
            return@CommentActionListener
        }
        isSubmittingComment = false
        boxBinding.editComment.isEnabled = true
        if (succeeded) {
            boxBinding.btnSubmitReply.isEnabled = false
            getCommentAdapter().setHighlightCommentId(0, false)
            getCommentAdapter().setReplyTargetComment(0)
            getCommentAdapter().replaceComment(fakeCommentId, newComment)
            getCommentAdapter().refreshPost()
            setReplyToCommentId(0, false)
            boxBinding.editComment.autoSaveTextHelper.clearSavedText(boxBinding.editComment)
        } else {
            boxBinding.editComment.setText(commentText)
            boxBinding.btnSubmitReply.isEnabled = true
            getCommentAdapter().removeComment(fakeCommentId)
            ToastUtils.showToast(this, R.string.reader_toast_err_comment_failed, ToastUtils.Duration.LONG)
        }
        checkEmptyView()
    }
}
阅读指南

先抓住这几个点

1. 这个流程是乐观更新

评论一发送，就会先在本地出现；用户不会等到网络返回才看到自己的内容。

2. 发送前不会做离线排队

这里和发帖流程不同，没有离线任务队列；NetworkUtils.checkConnection() 不通过就直接返回。

3. 回复与普通评论是两条路径

普通评论走帖子回复接口，回复评论走指定父评论的回复接口，最终都落到同一个本地列表。

4. 成功和失败都要清理 UI 状态

成功后要把假评论替换成真实评论并清空草稿；失败后要恢复文本、重新启用按钮并删除占位。

5. 全屏编辑只是输入辅助

CommentFullScreenDialogFragment 不负责提交，只负责收集和回传文本，确认后才进入发送链路。

6. 目标评论会被高亮

回复状态下会高亮被回复的评论，并把它滚动到可见位置，帮助用户确认上下文。
